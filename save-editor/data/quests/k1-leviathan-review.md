# KotOR 1 Leviathan quests: review chain

IDs only: quest tags, stage numbers, dialog and script resrefs with node numbers, item resrefs and tags, global names. Run build.py with --review-text for a local copy of this page with the game's own names and journal text (data/quests/local/, not committed).

Generated by `save-editor/tools/questdb/build.py` from the game files (journal from Override). Each stage lists who sets it, what must be true first, and what happens. Steps with a branch are alternatives: apply one branch, not all of them. Steps without a branch always happen. To check a stage, play it and compare the globals, items and XP.

Data file: `k1-leviathan.json`. Its `checked` flag stays false until a person has played these chains.

How to read a stage:

- A step without a branch always happens when the stage is reached that way.
- *way N* names one of several setters of the same stage (another dialog line or script). Use one way.
- *choice* is a player reply (or the NPC line that follows it) within two lines after the line that sets the stage. Pick the one the player would have taken.
- *if ...* is a branch inside a script; the game picks it from the save's state (globals, items, the player's alignment).
- *before this line* is the script on the line just before the one that sets the stage.
- Needs come from the dialog's condition scripts along the shortest path from the start of the conversation, and from the conditions a script checks before the effect.
- Items in needs and in "take" are matched by item tag, as the scripts do; items given are named by template resref.
- XP on a dialog line is the line's plot XP: plot.2da XP times the line's percentage, computed with the engine's rounding (two ceilings), so 20% of 500 gives 105.
- In the JSON, a dialog step's `via.list` says whether `node` indexes the entry list or the reply list; a journal need carries `op` like a global number need.
